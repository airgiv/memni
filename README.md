# memni — видео-мемы с вами и друзьями (тестовая версия)

Пользователь выбирает готовый видео-мем и назначает людей на роли. Затем он загружает их фото, настраивает образы и подтверждает промежуточные изображения. После этого запускается видео с **оригинальным звуком** шаблона.

Стек: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4, библиотека [@rapui/react](https://rapui.dev). Для реального режима — Supabase: Postgres, Auth и приватное Storage. Фоновый обработчик на Node использует FFmpeg.

> **Сейчас приложение работает в демонстрационном режиме.** Ключей моделей и Supabase нет, поэтому вместо генераций показываются явно помеченные примеры. Это не результат обработки ваших фото. Деньги не списываются.

---

## Быстрый старт

```bash
npm install
npm run dev          # Next.js (http://localhost:3000) + фоновый обработчик одной командой
```

Production-режим:

```bash
npm run build
npm start            # веб-сервер
npm run worker       # фоновый обработчик — отдельный процесс
```

Проверки:

```bash
npm run typecheck
npm test                                   # модульные тесты: домен, Telegram initData, FFmpeg-сборка, провайдеры
BASE_URL=http://localhost:3000 npm run e2e # сквозной сценарий по HTTP (нужны запущенные сервер и обработчик)
npm run media:demo                         # пересоздать демо-материалы шаблонов
```

Нужен Node.js 22.13 или новее: демо-бэкенд использует встроенный `node:sqlite`.

## Что внутри

### Пользовательский путь

1. **Каталог** (`/`). Пример воспроизводится со звуком по нажатию. На карточке видны число участников, длительность и цена либо честная отметка «Тестовая генерация». Есть главный шаблон **Hotel Lobby** на 2 роли и два демо-шаблона: на 1 и на 3 роли.
2. **Роли** (`/create/[draftId]?s=cast`). На неподвижном опорном кадре подсвечена текущая роль, например «Кто будет у микрофона слева?». Человека можно выбрать из сохранённых или добавить нового. У каждой роли есть карточка. Людей можно заменить, убрать или поменять местами; если выбрать человека, который уже стоит в другой роли, он поменяется местами.
3. **Подготовка человека**. Вкладки «Фото / Образ / Превью».
   - **Фото**: визуальные подсказки и требования конкретного шаблона. Сервер проверяет тип, размер и разрешение. Есть основное фото, дополнительные референсы и выбор главного. Человека можно сохранить для следующих роликов. Оценки «качества лица» нет, потому что анализатор лица не подключён.
   - **Образ**: одежда с фото, одежда из мема или вариант, предусмотренный шаблоном. В необязательном блоке — очки и добровольные уточнения внешности. Пол автоматически не определяется.
   - **Превью**: доступно «подтвердить», «изменить настройки», «заменить фото», «другой вариант». Вся история вариантов сохраняется. Выбрать и подтвердить прежний вариант можно бесплатно.
4. **Сцена**: только те настройки, которые поддерживает сценарий шаблона. Финальное фото показывает состав, внешность и расположение людей и требует подтверждения.
5. **Видео**: показаны подтверждённое фото, длительность, оригинальный звук, цена или «Тестовая генерация», а также список входов, которые получит видеомодель.
6. **Заказ** (`/orders/[jobId]`). Показываются реальные этапы: очередь, генерация, сборка со звуком, готово или ошибка. Процент выполнения не выдумывается. Страницу можно закрыть и вернуться. После завершения доступны просмотр со звуком, скачивание, «Другой мем с теми же людьми» и блок будущей оплаты (тестовый заказ).
7. **Мои люди** (`/people`): удаление человека вместе со всеми фото и образами. **Мои видео** (`/orders`).

На десктопе крупное превью стоит слева, настройки справа, а основное действие закреплено внизу колонки. На телефоне экраны идут последовательно, и одно главное действие закреплено под пальцем. Анимации — из словаря rapui (`fun:` / `animate-*`); они отключаются при `prefers-reduced-motion`. Звуки интерфейса выключены (`<SoundProvider enabled={false}>`).

### Архитектура

```
src/lib/templates/        конфигурация шаблонов (роли, области на кадре, требования, настройки, версия промптов, цена)
src/lib/domain/           чистая логика: черновик, отпечатки входных данных, промпты
src/lib/providers/image/  контракт + demo + Gemini (прямой API)
src/lib/providers/video/  контракт + demo + Kling (прямой API) + Genjutsu (Higgsfield)
src/lib/server/repo/      хранилище данных: local (SQLite, демо) и Supabase — один интерфейс
src/lib/server/storage/   приватные файлы: .data/files или приватный bucket Supabase
src/lib/server/services/  черновики, люди и фото, превью, задания, шаги обработчика
src/lib/server/media.ts   FFmpeg: сборка с оригинальным звуком и проверка результата
src/app/api/**            серверные операции (Route Handlers)
worker/index.ts           фоновый обработчик: аренда заданий, отправка, опрос, скачивание, сборка
supabase/migrations/      схема Postgres, RLS, приватный bucket, атомарные SQL-функции
src/components/**         интерфейс; src/ui/* — клиентская граница для rapui
```

**Подтверждения и устаревшие ответы.** Каждое превью хранит отпечаток входов, из которых оно сделано: фото, главное фото, образ, роль, версия шаблона и промптов. Подтверждение действует, только пока отпечаток совпадает с текущими данными.

- Любое изменение фото, ролей или влияющих на внешность настроек снимает подтверждение. Старый вариант остаётся в истории с пометкой «прежние настройки».
- Запоздавший ответ генерации попадает в историю, но не становится текущим вариантом и не может быть подтверждён.
- Черновик версионируется. Запись с устаревшей версией получает 409, а клиент не применяет ответы старее того, что уже показывает.

**Деньги и повторы.**

- Бесплатные превью считаются на сервере атомарно (`reserve_preview` в Postgres, транзакция в SQLite). Лимит настраивается через `FREE_PREVIEWS_PER_USER`; в интерфейсе он не зашит.
- Повторный клик, пока превью готовится, возвращает тот же запрос. Неудачное превью не расходует лимит, но его стоимость остаётся в учёте.
- Ключ идемпотентности видео строится из подтверждённой сцены. Повторное или параллельное нажатие возвращает то же задание.
- Счётчик попыток и собственный внешний id сохраняются **до** вызова провайдера. После сетевого тайм-аута задание не отправляется повторно вслепую: либо поиск по внешнему id, либо статус «нужна ручная проверка».
- Есть лимиты параллельных заданий (на пользователя и общий), дневной лимит и бюджет попыток. Повтор делается только вручную.
- Вход задания замораживается: копии утверждённых изображений, промпт и версия шаблона. Правки черновика после запуска на задание не влияют.
- Webhook провайдера не доверяется: он только просит обработчик сразу спросить настоящий статус у API.

**Оригинальный звук.** В шаблоне хранятся аудиодорожка и точные границы (`media.audio.startSec/endSec`). Обработчик накладывает её через FFmpeg и проверяет результат через ffprobe: есть ли звук и совпадает ли длительность. Песня никогда не ускоряется и не замедляется. Если расхождение не больше `DURATION_TOLERANCE_SEC`, видео обрезается или удерживается последний кадр. Большее расхождение даёт статус «нужна ручная проверка» с понятным текстом.

**Приватность и доступ.**

- Фото хранятся только в приватном хранилище, не в localStorage. При загрузке EXIF (в том числе GPS) удаляется.
- Каждый запрос к черновику, заданию, человеку или файлу ищет запись вместе с id пользователя. Чужое выглядит как «не найдено».
- В демо сессия лежит в HttpOnly-cookie с HMAC-подписью. В Supabase-режиме используется Supabase Auth, а RLS разрешает владельцу только чтение; запись идёт только через сервер.

### Интеграция rapui

- Из пакета используются Button, Card, Badge, Alert, Dialog, AlertDialog, Drawer, Collapsible, RadioGroup (card), ToggleGroup, Switch, Input, Textarea, FormField, Avatar, Skeleton, Spinner, EmptyState, FancyIcon, Tooltip, Toaster, VideoPlayer, Display/Lead/Accent и иконки. Предметные части — разметка ролей на кадре, шаги, история вариантов — собраны на токенах rapui (`bg-surface`, `rounded-card`, `ease-rm`, `fun:` …).
- В `@rapui/react@0.1.0` нет директив `"use client"`. Поэтому `src/ui/rapui.ts` служит клиентской границей с явными реэкспортами: `export *` в клиентской границе App Router запрещён.
- Путь «`theme.css` + `@source`» из README библиотеки не несёт ключевые кадры и CSS отдельных компонентов. Поэтому подключены оба слоя: предкомпилированный `@rapui/react/styles.css` и `@import "@rapui/react/theme.css"` для собственных утилит (`src/app/globals.css`).
- Две локальные обёртки вместо правки библиотеки:
  - `src/ui/VideoPlayer.tsx`: плеер решает во время рендера, показывать ли кнопку PiP, по `document.pictureInPictureEnabled`, а это вызывает рассинхронизацию при гидрации. Обёртка монтирует плеер после гидрации.
  - `src/ui/Switch.tsx`: русские подписи вместо «on/off».

  Обе проблемы стоит исправить в самой библиотеке.

### Telegram Mini App

- Тот же конструктор и тот же сервер. `TelegramBridge` подключает скрипт Telegram только при запуске внутри Telegram (`#tgWebAppData`). Внутри Telegram он вызывает `ready/expand`, берёт тему из Telegram, выставляет безопасные отступы в CSS-переменные и связывает кнопку «Назад» с роутером.
- `POST /api/auth/telegram` проверяет подпись initData по документированному алгоритму (HMAC «WebAppData»), а затем создаёт или находит пользователя. Без `TELEGRAM_BOT_TOKEN` вход отвечает «не настроен».
- **Интеграция не завершена**: с настоящим ботом внутри Telegram не проверялась. Перенос черновиков гостевой сессии в аккаунт Telegram не реализован.
- Для цифровых продаж внутри Telegram предусмотрены Stars (валюта `XTR` в `Price`, кнопка-заглушка на странице заказа).

### Платежи

Деньги не списываются. При запуске видео создаётся тестовый заказ (`orders.status = 'test'`). На странице заказа показан будущий блок оплаты («Картой — скоро», «Telegram Stars — скоро»). Цена хранится в шаблоне; 99 ₽ у Hotel Lobby помечены как пример (`isExample: true`).

## Шаблоны и материалы

Шаблоны описаны в `src/lib/templates/index.ts`: название, описание, пример, исходный ролик, аудио с границами, длительность, формат, опорный кадр, роли со стабильными id и областями на кадре, требования к фото, настройки образа и сцены, версия промптов, настройки провайдера и цена. Роли размечаются один раз вручную; распознавания для каждого пользователя нет.

**Все медиа сейчас демонстрационные.** Их рисует `scripts/make-demo-media.ts`: иллюстрированный кадр, синтетический ролик движения и синтезированная мелодия. Чужие ролики не скачивались.

Как подключить реальный шаблон:

1. Положите лицензированные `source.mp4` (ролик движения), `audio.m4a` (оригинальный звук), `example.mp4` и `frame.jpg` (опорный кадр) в `public/templates/<id>/`, CDN или bucket.
2. Укажите точные `startSec/endSec` звука и ролика и длительность.
3. Разметьте роли на новом кадре (`region` в долях 0..1).
4. Поставьте `demoMaterials: false`, увеличьте `version` и выполните `npm run seed:templates` (для Supabase).

## Реальный режим: настройка

1. `cp .env.example .env.local` и заполните ключи.
2. Supabase:
   - примените `supabase/migrations/0001_init.sql` (`supabase db push` или SQL Editor);
   - включите **Anonymous sign-ins** в Auth;
   - выполните `npm run seed:templates`.
3. Обработчик — на сервере с FFmpeg (`FFMPEG_PATH`/`FFPROBE_PATH` или npm-бинарники). Нужен публичный HTTPS-адрес, чтобы видеосервис мог скачать исходный ролик (`TEMPLATE_MEDIA_BASE_URL`) и прислать webhook (`VIDEO_WEBHOOK_URL`).
4. Лимит бесплатных превью: `FREE_PREVIEWS_PER_USER`. Для Hotel Lobby нужно минимум 3 изображения (2 образа + сцена). Значение 2 из брифа не даёт пройти этот шаблон, поэтому по умолчанию стоит 8.

## Что проверено и как

### На демонстрационных данных — проверено

| Что | Как |
|---|---|
| Production-сборка и типы | `next build`, `tsc --noEmit` — без ошибок |
| Полный путь на телефоне (iPhone 13) и десктопе (1440×900) | Playwright + Chromium: каталог → роли → фото → образ → превью → подтверждение ×2 → сцена → видео → готовый результат → «Мои люди». Ошибок в консоли нет |
| Возврат к черновику после перезагрузки | Перезагрузка на шаге «Видео» возвращает на тот же шаг; черновик хранится на сервере |
| Назначение, замена, обмен ролей | e2e и модульные тесты |
| Снятие подтверждения | e2e: новое фото, смена образа или обмен ролями снимают подтверждение; прежний вариант остаётся в истории |
| Устаревший ответ и повторный запуск | e2e: запоздавшее превью не выбирается и не подтверждается; двойной клик на превью и тройной (в том числе параллельный) на видео не создают дублей; устаревшая версия черновика даёт 409 |
| Ошибки и повтор | e2e: имитация ошибки превью (лимит возвращается) и ошибки видео; ручной повтор; исчерпание бюджета попыток |
| Исчерпание лимита превью | e2e: 429 с понятным текстом, счётчик на сервере |
| Разграничение доступа (локальный бэкенд) | e2e: второй пользователь получает 404 на черновик, задание, видео, фото, превью и удаление человека; поддельная cookie отклоняется |
| Звук в результате | ffprobe: у демо-результата есть аудиодорожка, длительность ровно 8,00 с. Модульный тест собирает ролики 7,8 / 8,0 / 8,2 с и проверяет, что при 5 с выдаётся ошибка, а не растяжение |
| Проверка Telegram initData | Модульные тесты: верная подпись, подмена данных, чужой бот, просроченные данные |

### Реальными API-вызовами — НЕ проверено

- **Gemini (изображения)**: адаптер написан по исходникам официального SDK Google (поля REST, причины блокировки). Названия моделей и цены взяты из выдержек ai.google.dev: прямой доступ к документации из среды разработки был закрыт. Реальных вызовов не было, ключа нет.
- **Kling (видео, Motion Control)**: эндпоинты и поля — по выдержкам из официальной документации, сама страница была недоступна. Не подтверждены: `external_task_id` для этого эндпоинта, поиск задания по нему, формат подписи webhook, тарифы Motion Control. Motion Control принимает **одно** изображение персонажа, поэтому отдельные фото участников не передаются (интерфейс говорит об этом явно). Движется ли корректно двое людей по одному референсу, нужно проверить на реальном материале.
- **Genjutsu (Higgsfield)**: эндпоинт и поля — по выдержкам docs.higgsfield.ai. Формат готового ответа не подтверждён. Принимает до 8 изображений, поэтому отдельные референсы участников передаются.
- **Supabase**: схема, RLS, SQL-функции и репозиторий написаны и прошли проверку типов, но к живому проекту не применялись. Разграничение доступа в реальном режиме не проверено.
- **Telegram**: вход с настоящим ботом внутри Telegram не проверялся.
- **Звук в реальном результате**: сборка проверена на демо-роликах; на ответе настоящего видеосервиса — нет.
